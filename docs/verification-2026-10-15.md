# VORS — протокол демонстрационной проверки

**Дата:** 15 октября 2026 года\
**Область:** локальная рабочая копия Telegram Mini App и бота; визуальная проверка мобильного интерфейса.\
**Статус:** технический прототип / MVP в разработке, не подтверждённый production-релиз.

## Что проверено

| Объект | Выполненная проверка | Результат |
|---|---|---|
| Mini App | `npm run typecheck` | exit 0 |
| Mini App | `npm run build` | exit 0 |
| Bot | `npx tsc --noEmit -p tsconfig.json` | exit 0 |
| Bot | `npm run build` | exit 0 |
| Видеогайд | `npm run build` (проверка типов) | exit 0 |
| Браузер | Шесть шагов заявки, навигация вперёд/назад, валидация, сохранение вводимых значений, резюме | Проверено локально |
| Браузер | Открытие поиска статуса и обработка ошибок | Проверено локально |
| Адаптивность | Основные страницы при ширине 320, 390, 430 px | Основной контент помещается; остаются UX-замечания |

Проверки сборок Mini App и бота выполнены в отдельных временных копиях, без рабочих `.env`. В процессе сборки Next.js сообщал об устаревших данных `caniuse-lite`; ошибка сборки не возникла.

## Что не проверялось сквозным сценарием

- Реальная отправка заявки в действующие Telegram/Supabase.
- Фактическая загрузка референса во внешнее хранилище.
- Получение статуса зарегистрированной заявки и доставка уведомления.
- Проверка работы в реальном Telegram WebView на iOS/Android с системной клавиатурой.
- Полная безопасность и готовность к эксплуатации с персональными данными пользователей.

Серверная проверка контекста Telegram и устойчивость интеграционных операций требуют доработки и отдельного аудита перед использованием реальных заявок.
